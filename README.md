# Vamgar (وام‌گر)

**AI Merchant Credit & Working Capital Engine**

Vamgar (از «وام‌گر») یک موتور تصمیم‌گیری اعتباری برای کسب‌وکارهای خرد ایرانی است. هدف این پروژه این است که با استفاده از داده‌های واقعیِ تراکنشی (کارت‌خوان، تسویه PSP، سفارش‌های مارکت‌پلیس) به‌جای صورت مالی رسمی یا وثیقه، به بانک‌ها، PSPها، لندتک‌ها و مارکت‌پلیس‌ها کمک کند تصمیم بگیرند:

- به این مرچنت چقدر اعتبار بدهند (سقف امن اعتبار)
- با چه مدل بازپرداختی (اقساط ثابت در برابر درصدی از فروش روزانه)
- ریسک واقعی cash gap این کسب‌وکار چقدر است

## چرا Vamgar؟

مرچنت‌های خرد فروش و تراکنش دارند، اما داده رسمی (صورت مالی، سابقه اعتباری، وثیقه) کم دارند. این حلقه باعث می‌شود یا رد شوند یا با فرایندهای سنگین (چک، ضامن) مواجه شوند. Vamgar داده‌های پراکنده تراکنشی را به یک تصویر ریسک و ظرفیت بازپرداخت تبدیل می‌کند — قبل از اینکه اعتباردهنده کور تصمیم بگیرد.

## مدل کسب‌وکار

جزئیات کامل ایده، بازار هدف، مدل درآمدی و استراتژی محصول در [`docs/business-model.md`](docs/business-model.md) آمده است.

### API

همه endpointها (به‌جز `/health`) اگر `VAMGAR_API_KEYS` ست شده باشد نیاز به هدر `X-API-Key` دارند (به بخش «احراز هویت» زیر مراجعه کن).

| Endpoint | ورودی | خروجی |
|---|---|---|
| `GET /health` | — | وضعیت سرویس (بدون نیاز به API key) |
| `POST /score/transactions` | تراکنش‌های خام مرچنت (کارت‌خوان/PSP/مارکت‌پلیس) | تصمیم اعتباری کامل (پایپ‌لاین واقعی: تحلیل cash gap + خلاصه فروش) |
| `POST /score/csv` | export دوره‌ای CSV یک منبع (ستون تاریخ + مبلغ) + `merchant_id` + `source` | تصمیم اعتباری کامل، بعد از تبدیل CSV به تراکنش خام |
| `POST /score/xlsx` | فایل xlsx (multipart، فیلد `file`) + `merchant_id` + `source` | تصمیم اعتباری کامل، بعد از تبدیل xlsx به تراکنش خام |
| `POST /cashflow/analyze` | تراکنش‌های خام مرچنت | تحلیل cash gap (دوره‌ها، عمق، فراوانی) برای بازبینی |
| `POST /score` | خلاصه فروش از‌قبل‌تجمیع‌شده | تصمیم اعتباری (بدون تحلیل cash gap، برای فراخوان‌هایی که خودشان داده تجمیع‌شده دارند) |
| `GET /merchants/{merchant_id}/history` | — (query اختیاری `limit`) | تاریخچه تصمیم‌های اعتباری ثبت‌شده آن مرچنت (جدیدترین اول) |

منطق `cashflow.py` جریان نقدی روزانه واقعی مرچنت را از تراکنش‌های خام می‌سازد، موجودی تجمعی را دنبال می‌کند و هر دوره‌ای که این موجودی منفی می‌شود را به‌عنوان یک cash gap (با عمق و مدت دقیق) ثبت می‌کند. موتور امتیازدهی در `engine.py` این عمق/فراوانی را در محاسبه ریسک، سقف اعتبار پیشنهادی و انتخاب مدل بازپرداخت (ثابت در برابر درصدی از فروش) لحاظ می‌کند.

`importers.py` اولین قدم اتصال به داده واقعی است: export دوره‌ای CSV یا xlsx (فرمت رایج کارت‌خوان/PSP/مارکت‌پلیس) را به مدل `Transaction` تبدیل می‌کند. اتصال زنده به API این منابع (به‌جای export دستی) هنوز پیاده نشده — نگاه کن به Issueهای باز پروژه.

### Persistence

سرویس قبلاً کاملاً stateless بود؛ حالا `storage.py` یک لایه SQLite سبک اضافه می‌کند:
- هر تراکنش import‌شده idempotent ذخیره می‌شود (import تکراری همان داده رکورد تکراری نمی‌سازد).
- هر `CreditDecision` صادرشده در تاریخچه مرچنت ثبت می‌شود و از `GET /merchants/{merchant_id}/history` قابل بازیابی است.
- مسیر فایل دیتابیس با متغیر محیطی `VAMGAR_DB_PATH` قابل تنظیم است (پیش‌فرض: `vamgar.db` کنار پروژه).

### احراز هویت

اگر `VAMGAR_API_KEYS` (کلیدهای مجاز، جدا شده با کاما) ست شده باشد، همه endpointها (به‌جز `/health`) به هدر `X-API-Key` معتبر نیاز دارند؛ در غیر این صورت سرویس در حالت توسعه محلی بدون احراز هویت کار می‌کند. **قبل از استقرار واقعی حتماً `VAMGAR_API_KEYS` را ست کن.** این لایه فعلاً چندمستأجری کامل (محدودسازی هر کلاینت فقط به مرچنت‌های خودش) را پیاده نمی‌کند.

## اجرای محلی

```bash
pip install -r requirements.txt
uvicorn src.vamgar.main:app --reload
```

### داشبورد

رابط مدیریتی فارسی و راست‌به‌چپ از مسیر [`/app`](http://localhost:8000/app) در دسترس است. داشبورد شاخص‌های اعتباری، روند فروش، تحلیل cash gap و منابع داده را نمایش می‌دهد و فرم «ارزیابی جدید» مستقیماً به `POST /score/transactions` متصل است.

## وضعیت

🚧 هسته امتیازدهی، تحلیل cash gap واقعی، import CSV/xlsx، persistence سبک و احراز هویت پایه پیاده‌سازی و تست شده‌اند. باقی‌مانده backlog (اتصال زنده API کارت‌خوان/PSP/مارکت‌پلیس، چندمستأجری کامل) در Issueهای باز پروژه پیگیری می‌شود.
